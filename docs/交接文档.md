## 1. 这是个什么系统

**世界弹射物语（World Flipper）CN 1.8.1 的私服**，面向一群玩家长期运营。由三部分组成：

1. **服务端**（自己写的，不是官方）：实现游戏客户端说的那套 HTTP 协议（`/api/index.php/*`）、存档（SQLite）、资源分发（CDN/补丁）、后台管理、Q 群机器人。
2. **登录门**：官方私服一般是「谁都能进」，我们加了账号体系——开屏弹面板，注册/登录，账号绑到 QQ，15 天免登录。安卓（AS3 注入 + APK）与 iOS（越狱 dylib）各一套客户端实现。
3. **运维设施**：云端 watchdog（进程守卫）、内容版本与补丁链、玩家侧资源导入包（给网络差/资源损坏的玩家）。

### 玩家视角的流程

```
装客户端 → 开屏「登录门」→ 注册（用户名+密码+确认）→ 拿验证码
        → 到 QQ 群发 /bind <验证码> → 账号激活 → 游戏内登录成功
        → 之后 15 天免登录；换号就在门里登另一个账号，游戏跟着换（"并号"）
```

### 账号与身份模型（改代码前必须懂，出事最多的地方）

* **设备号**：游戏自己写在客户端容器里（iOS/安卓都有），13~15 位数字。**服务端按设备号认账号**（表 `device_bindings`）。
* **绑定闸（bind gate）**：没绑定的设备调 `/api/index.php/tool/signup` 会收到 `result_code 517`，客户端表现为「进不去」。
* **并号（device-follow）**：在登录门里登录账号 A 之后，同一台机器的游戏会被自动改绑到 A。实现是「门的登录记下来源（容器键/IP）+ 游戏的报到/`/load` 命中同来源就改绑」，状态落在 `<DATA_DIR>/device-follow-state.json`。
* **免登录**：客户端本地会话 15 天，服务端不参与。

| 部分 | 技术 | 仓库 | 产物 |

### 服务器上的目录（真实路径）

```
D:\starpoint-cn\
├─ platform\                 ← 服务端部署目录（"平台"）

│   ├─ tools\start_cn.cjs    ← 启动器（读 .env，拉起 out/cn-server.js）
│   ├─ .env                  ← 全部开关与密码（见 §5.1）

│   └─ _deploy\              ← 运维脚本（restart-cn.cmd 等）
├─ .database\                ← SQLite 存档：wdfp_data.db（+wal/shm）、device-follow-state.json
```

## 4. 五分钟自检（接手第一天必做）

```powershell
# 1) 服务在不在
curl.exe -s http://<IP>:8001/healthz          # 期望：ok（只回 ok，不是 JSON）
# 2) 内容版本对不对（应回 1.4.57 规划）
curl.exe -s -X POST http://<IP>:8001/api/index.php/asset/get_path ^
  -H "Content-Type: application/json" -d "{\"device_id\":1,\"target_asset_version\":\"1.4.54\"}"
# 3) 补丁链通不通（应回 206）
curl.exe -s -o NUL -w "%{http_code}" -r 0-1023 "http://<IP>:8001/patch/cn/archive-common-diff/pinball-1.4.56-1.4.57-1-<hash>.zip"

# 5) 机器人活不活（群里发 /bind 测试码，或看日志）
\\<IP>\D$\starpoint-cn\platform\logs\watchdog.log
```

## 5. 日常运维

### 5.1 `.env` 关键开关（`platform\.env`）

| 变量 | 当前值 | 含义 / 注意 |
| --- | --- | --- |
| `DATA_DIR` / `CDN_DIR` | `D:\starpoint-cn\.database` / `.cdn` | 数据与资源根目录 |
| `CN_LISTEN_HOST` / `CN_LISTEN_PORT` | `0.0.0.0` / `8001` | 游戏 API 端口 |
| `SESSION_PORT` | `8003` | TCP 会话端口（共斗等用） |
| `ASSET_MODE` | `local` | 资源走本地 `.cdn` |
| `IOS_COMPAT_ENABLED` | **`1`** | **删了它整套 iOS/leiting 插件不注册，游戏每个请求 404** |
| `BIND_GATE_ENABLED` | `1` | 绑定闸（未绑定设备 517） |
| `GAME_AUTH_MODE` | `audit` | `audit`=只记录不拦；确认无玩家被拒后改 `enforce` |
| `SHOP_CAMPAIGN_PERIOD_TOLERANT` | `1` | 放过已过期的活动档期（否则商店整页 1652） |
| `SP_DEVICE_FOLLOW`(+两个 TTL) | 开 / 30min / 5min | 并号；关掉会导致「换号不生效」 |
| `SP_DIAG_ENABLED` / `SP_DIAG_FILE` | `1` / `logs\sp-diag.log` | 安卓客户端日志回传（排障神器） |

### 5.2 启动 / 停止 / 重启

* 全部：服务器上双击 `start-starpoint.bat`（server → napcat → bot），停用 `stop-starpoint.bat`。
* 只重启服务端：跑 `platform\_deploy\restart-cn.cmd`（脚本会按名字杀 `cn-server.js` 再拉起）。
* **远程重启（推荐）**：`schtasks` 在云端已失效（`Access is denied`），用一次性服务：

```powershell
sc.exe \\<IP> create StarPointRestart binPath= "cmd.exe /c D:\starpoint-cn\platform\_deploy\restart-cn.cmd" start= demand
sc.exe \\<IP> start StarPointRestart      # 报 1053 是正常的，命令已执行
sc.exe \\<IP> delete StarPointRestart
```

* 内容启动约 **80 秒**；`restart-cn.cmd` 不校验结果，靠 watchdog 兜（最多 ~1 分钟不可用）。

### 5.3 watchdog（进程守卫）

* 计划任务 `StarPointCN-Watchdog`（开机自启、管理员、最高权限），脚本 `platform\_deploy-20261019\watchdog.ps1`。
* 行为：每 15 s 探 `http://127.0.0.1:8001/healthz`，连续 4 次失败就杀掉残留进程并重启 server；机器人掉了也会拉起来。NapCat 只报不自动重启（重登要扫码）。
* 日志：`platform\logs\watchdog.log`。

### 5.4 备份 / 回滚

```powershell
# 备份（服务端目录下）
Copy-Item .\out .\out.bak-YYYYMMDD -Recurse
Copy-Item D:\starpoint-cn\.database\wdfp_data.db D:\starpoint-cn\.database\wdfp_data.db.bak-YYYYMMDD
# 回滚：把 out 换回备份、重启；只回滚代码不要回滚数据库（会丢玩家进度）
```

内容库另有 `store.bak-*`（`D:\starpoint-cn\platform\content\store` 旁），改内容前先复制一份。

### 5.5 部署服务端改动（最常用的操作）

1. 本地改代码 → `npm run build:server`（必须 `CN build verified`）。
2. 把要更新的文件（通常整个 `out/`）打包成 **一个 zip**（逐个文件拷过 SMB 很慢）。
3. `cmd /c "net use \\<IP>\D$ /user:administrator <密码>"`，把 zip 拷到 `\\<IP>\D$\starpoint-cn\platform\_deploy\`。
4. 远端解包 + 覆盖：`tar -xf xxx.zip -C stage` 然后 `xcopy /E /Y /I /Q stage\out\* out\`。
5. §5.2 的重启 → `curl http://<IP>:8001/healthz` 回 `ok`。
6. 抽查关键文件哈希（`Get-FileHash`）与本地一致，别只看时间戳（tsc 增量会保留旧 mtime）。

### 5.6 更新内容 / 补丁链（改游戏版本时）

* 资源根 `D:\starpoint-cn\.cdn`：`cn\` 放归档（`archive-*-full|diff`），`patches\` 放补丁包（每档一个 `manifest.json` + 各层归档）。
* 服务端报给客户端的目标版本 = `BUNDLED_CDN_CATALOG_VERSION`（代码里，当前 1.4.54）+ 补丁链推导（实际 1.4.57）。
* **补丁链必须连续**：`1.4.53→54→55→56→57`。缺一环客户端会 `PATCH_BASE_VERSION_MISSING`，服务起不来（有实例：只放 54→57 三段，重启直接起不来）。
* ⚠️ **不要单边把目标版本退回旧版本**：玩家客户端升上去之后，回退会让它卡在 5.96% 报 H400。

### 5.7 数据库

* 文件：`D:\starpoint-cn\.database\wdfp_data.db`（WAL 模式，另有 `-wal`/`-shm`）。
* 只读查看：**先连同 `-wal`/`-shm` 拷到本机临时目录**再 `sqlite3 -readonly` 打开（直接在共享路径上开会有锁风险）。
* 关键表：`accounts`（账号）、`players`（角色/进度）、`device_bindings`（设备→账号）、`bind_audit`(绑定审计)、`device_grants`、`sessions` 不在 SQLite（服务端内存/Redis 语义，重启会掉，属正常）。

## 6. 发布流程

### 6.1 服务端

见 §5.5。给公网的「补丁包」（整棵 `out/` + 部署说明）作为 GitHub Release 附件发布（历史 tag：`server-patch-*`）。

### 6.2 安卓客户端（三变体 APK）

仓库：`SPLogin-android`。需要 Windows + `STARVIEW_HOME`（starview 工具链）与 Adobe AIR SDK（用游戏原 SWF 做载体）。

```powershell
python tools\mk-android-patch.py --carrier <载体 SWF 解包目录>\scripts\PinballClientMain.as `
                                 --swf <原版 worldflipper_android_release.swf>
powershell -File tools\build-android-apks.ps1 -Only all `
    -LanHost <局域网服务器 host:port> -PubHost <公网服务器 host:port>
python tools\verify-android.py out\testA.apk --host <局域网 host:port>
python tools\assemble-android.py --lan-host <局域网 host:port>
```

* 构建自带两道硬闸：`audit5`（补丁完整性）、`audit7`（**只能用游戏自己用过的 AS3 API**——`Graphics.cubicCurveTo` 这类新 API 真机会抛 `Error #1056`，构建会直接失败）。要新画图形只能用 `moveTo/lineTo/curveTo/lineStyle/beginFill/drawCircle`。
* 产物固定约 168 MB，用仓库自带 keystore（`signing\wf.keystore`，别名 `wf`）签名；**必须与我们其余 APK 同证书**，否则覆盖安装会失败/丢存档。
* 版本号要同步改 5 处：`SpLoginGate.as` 的 `VERSION`、`mk-android-patch.py` 的横幅、`verify-android.py` 的记号、`assemble-android.py` 的 `VERSION`、`docs/` 与 `README.md`。
* 发版：把 APK 传 GitHub Release（`v1.xx` tag），并刷新 `base-apk` tag 里的占位包（CI 的「换地址重打包」流水线拿它当基准，只能放一个 APK）。

### 6.3 iOS 客户端（越狱 tweak）

仓库：`SPLogin-iOS`。**只需要 push**：CI 在 macOS runner 上编译 + 加固 + 出 `.deb`，也可手动触发并指定要烧进去的服务器地址。

* 静态加固（改名/加密字符串/清符号表）已接在 Makefile 的 `after-all::` 钩子里——**不要把它挪到构建外面**，`make package` 会重新链接把加固覆盖回去。
* 产物：`splogin-ios-{lan,pub}-<host>-<ver>.{dylib,deb}`，附 `checksums-*.txt`，发 Release。

### 6.4 玩家侧资源导入包（可选，网络差/资源损坏时用）

* 内容：一个改过的导入器 APK + 6 个分卷（tar 切卷，1.4.54 基线，全量 748 个归档 / 10.9 GB）。
* 导入器原版会**硬校验分卷 sha256**（写死了官方分卷的哈希），自建分卷必然过不了 ⇒ 我们放行了这一处校验（其余逻辑未动），并用我们自己证书重签（装回正式客户端不会被顶）。
* 分卷命名固定 `cn-cdn.tar.part.00`…`05`，必须同目录、按序。
* 发布在 `SPLogin-android` 的 Release（tag `cdn-1.4.54-all`）。

**① 主线 1-2 打完报 H500（每个账号首通必现，界面卡几秒）**
* 结算提交后构造响应没兜底：`src/routes/api/singleBattleQuest.ts` `buildSingleFinishResponse`（投影函数抛错就 500）。
* 首通奖励若含「已持有角色/装备」会重复 insert 撞唯一键（历史同类修复：mail 的 H500）。
* 「卡几秒」是因为数据库没设 `busy_timeout`（等锁 5 秒抛 `SQLITE_BUSY`）；主库只设了 WAL/foreign_keys。
* 修法：响应投影加 try/catch 降级 → 已持有角色改「数量 +1」 → 主库连接加 `busy_timeout=5000`。

**② 共斗（联机）打完回不了房，客户端弹 H404**
* 结算后 `releaseBattle()` 把房间状态从 4 改回 1，失败时只打一行 warn，房间就卡在 `raising_state=4`；握手对 state=4 一律拒绝（连本房成员也拒）。
* 修法：握手放行「记录内成员 + state=4」并按 returning-member 语义投影状态 1；release 失败交给 finish 幂等重试。
* 注意：**客户端把任何 4xx 都显示成「发生意想不到的错误 回到登录界面 (No.H404)」**，所以联机侧不要随便回 4xx。

### P1

**③ 星之粒一次换 7 个报错**：服务端没有数量上限、忽略 `api_count`，一次只兑 1 件；且失败原因（余额不足/已持有/不存在）全被压成同一个 `result_code 2053`，玩家看不出为什么。
→ 按原因给不同 result_code + 日志带原因。

**④ 交易所打不开（H500）**：`/shop/get_sales_list` 没 try/catch，档期字段缺失/为空数组时解析抛错；另有一处统计变量从不自增（容错分支实际没生效）。
→ 期档非法就跳过 + 外层兜底返回空列表。

**⑤ 部分玩家 C8601（资源报错）**：客户端本地资源表残缺（连「胡萝卜」这种开服基础道具都查不到）⇒ 九成是下载不完整。
→ 让玩家在登录界面「清除缓存」重下；或发 §6.4 的本地导入包。服务端数据无缺口，**不要**为了这个删数据。

**⑥ 主线 12 章入口不显示**：服务器时钟被固定在虚拟时间（约 2024-07/08），而 12 章的开放时间是 2024-12-19 ⇒ 全服一致地看不到。
→ 要么动虚拟时钟，要么给「未来档期」加开关（只在主线生效）。**业主决定不动时钟**，所以只能走开关。

**⑦ 玛娜板全服只显示 1 级**：同一根因（虚拟时钟 + 窗口判定）。130 个角色的窗口起点在未来。**业主暂定不改**，记录在案。

### P2

* **教程收尾/取名/首抽**：`tutorial` 路由整体没有 5xx 兜底；首抽结果为空时直接抛错（→500→闪退→重进重复）；名字没做非空/长度校验（空名会写库失败 500）。
* **属性抗性任务不推进**：任务表解析已修，但需要的内容映射表是空壳（内容同步生成物），要补数据。
* **`CN_RES_VERSION` 形同虚设**：代码里没有引用，真正生效的是 `BUNDLED_CDN_CATALOG_VERSION`；文档口径要改。
* **单文件资源兜底**在补丁目录为空时返回 404（客户端某些路径会用到）。

### P3

* iOS / 安卓客户端的真机验收清单（`SPLogin-android/docs/测试清单.md`）逐项过一遍。
* 上游仓库的性能回归基线目前全红（上游自身问题），**不要为了让测试变绿去刷新快照**。

## 9. 设计决策与「别做」清单

1. **虚拟时钟不动**（业主决定）。它影响任务/商店/玛娜板的开放时间判定，是全服一致的偏移，不是 bug。要放过某类内容就**加开关**，不要改时钟。
2. **上游同步以本 fork 为准**：与上游同名仓同步时，冲突/回归一律保留本仓实现，只吸收上游的更新功能。
3. **客户端资源包不加密、不校验签名之外的东西**——我们只保证「和官方清单同源 + 有 sha256 可自查」。
4. **登录门只做静态加固**（改名/字符串加密/清符号表），**不做**反调试/反 Frida/防改包。加密强度够挡住「随手逆向」即可。
5. **服务端不替客户端做资源版本升级**：目标版本由内容目录 + 补丁链推导，客户端自己比对下载。绝不为了某个玩家单方面降版本。
6. **不要提交别人的半成品**：仓库里可能长期存在他人未完成的改动（见 §11），提交前先 `git status` 看清楚。
7. **不要在公网服直接改 `src`**：服务器只有 `out/`，源码在 Git；线上只覆盖产物。

## 11. 排障手册（症状 → 先查什么）

| 症状 | 先查 | 常见原因 |
| --- | --- | --- |
| 玩家全部进不去、客户端报网络错 | `curl http://<IP>:8001/healthz` | 服务没起（watchdog 应自愈，看 `watchdog.log`）；或 `.env` 缺 `IOS_COMPAT_ENABLED=1` |
| 某个玩家进不去（517） | 数据库 `device_bindings` / `bind_audit` | 设备未绑；让其先在登录门登录一次（并号会改绑） |
| 换账号后游戏还是旧号 | `device-follow-state.json`、`bind_audit` 里 `followed_device_ids` | 门登录与游戏报到太久没对上（超过 TTL）；让他先登录门、5 分钟内进游戏 |
| 客户端卡在读条 5.96% 报 H400 | `asset/get_path` 返回的目标版本 | 目标版本被回退得比客户端 master 还旧 |
| 服务启动失败 `PATCH_BASE_VERSION_MISSING` | `.cdn\patches` 与 `.cdn\cn` 的归档 | 补丁链缺环（必须从 1.4.53→54 起连续） |
| 商店整页报 1652 | `.env` 的 `SHOP_CAMPAIGN_PERIOD_TOLERANT` | 开关没开 / 被覆盖 |
| 某功能 500 | `logs/cn-server.out.log` 里 `unhandled request failure` + 堆栈 | 见 §8 已有清单；先在本地复现再改 |
| 客户端闪退/报 C 系错误 | `logs/sp-diag.log`（客户端日志回传）、`[CRASH]` 行 | 资源残缺（C8601）多为下载不完整 |
| 机器人不回话 | `watchdog.log`、NapCat WebUI（6099） | NapCat 掉线要重新扫码 |

**日志注意**：`cn-server.out.log` 是逐行 JSON（pino），可以直接 grep `"statusCode":500`、`unhandled request failure`、`[DEVICE-FOLLOW]`。历史上有过 UTF-16/UTF-8 混写的旧日志，遇到乱码就用 `Get-Content -Encoding Unicode` 或直接换新日志。
